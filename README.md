# Life OS

Тайван, цэгцтэй хувийн "үйлдлийн систем": хянах самбар, календарь, ажлууд, зорилго ба төсөл, AI туслахын интерфейс, тэмдэглэл, төрсөн өдөр, мэдэгдэл, шинжилгээ, тохиргоо. Энгийн **HTML, CSS, vanilla JavaScript** (ES модуль, framework-гүй, build алхамгүй) дээр бүтээгдсэн бөгөөд **Supabase Auth + PostgreSQL**-тэй холбогдоход бэлэн бүтэцтэй.

Интерфейс бүхэлдээ монгол хэл дээр. Хурдан нэмэх талбар болон туслах нь монгол, англи өгүүлбэрийг хоёуланг нь ойлгоно.

---

## 1. Ажиллуулах

**Шууд үзэх:** `preview.html`-г давхар дарж нээнэ. Сервер хэрэггүй, жишээ өгөгдөлтэй ачаалагдана, өөрчлөлт хадгалагдахгүй. Энэ файлыг `node tools/build-preview.mjs` гэж js/ болон css/-ээс дахин үүсгэнэ.

**Бүрэн хувилбар (Supabase-тэй):** хөтөч `file://` хаягаар ES модуль ачаалдаггүй тул `index.html`-г локал сервероор нээнэ:

```bash
cd life-os
npx serve .                    # эсвэл
python3 -m http.server 5173    # дараа нь http://localhost:5173 нээнэ
```

VS Code-ийн **Live Server** өргөтгөл ч болно.

## 2. Хоёр горим

| Горим | Хэзээ | Өгөгдөл хаана байх вэ |
|---|---|---|
| **Session горим** | `js/config.js` доторх `SUPABASE_URL` / `SUPABASE_ANON_KEY` хоосон | Зөвхөн тухайн цонхны санах ойд. Дахин ачаалахад устна. Энэ тухай мэдэгдэл харагдана. |
| **Supabase горим** | Хоёулаа бөглөгдсөн | Таны Supabase өгөгдлийн сан, хэрэглэгч бүрээр (Row Level Security). |

**Хуурамч нэвтрэлт байхгүй**, **localStorage-ийг өгөгдлийн сан болгож ашигладаггүй**. `localStorage`-д зөвхөн харагдах тохиргоо (өнгө, цагийн формат, ажлын цаг, долоо хоногийн эхлэл, ажлын анхдагч утга) `lifeos.prefs` түлхүүрээр хадгалагдана. Supabase-ийн клиент өөрийн нэвтрэлтийн токеныг ердийнхөөрөө хадгална.

Session горимд туршихын тулд тодорхой шошготой **жишээ өгөгдөл** ачаалж болно (Хянах самбар → “Жишээ өгөгдөл ачаалах”, эсвэл Тохиргоо → Өгөгдөл ба холболт). Supabase холбогдсон үед энэ сонголт нуугдана — жишээ өгөгдөл таны санд хэзээ ч орохгүй.

## 3. Supabase холбох (алхам алхмаар)

1. **Түлхүүр.** Supabase Dashboard → *Project Settings → API*. **Project URL** болон **anon public** түлхүүрийг (эсвэл шинэ *publishable* түлхүүр) `js/config.js`-д хуулна:
   ```js
   export const SUPABASE_URL = 'https://xxxx.supabase.co';
   export const SUPABASE_ANON_KEY = 'eyJhbGciOi...';
   ```
   `service_role` / secret түлхүүрийг хэзээ ч бүү ашигла — илэрвэл апп ажиллахаас татгалзана.
2. **Хүснэгт.** Таны сан аль хэдийн байгаа тул `supabase/schema.sql`-ийг нээж харьцуулна:
   - Хүснэгт дутуу → түүний `create table` хэсгийг SQL Editor-т ажиллуулна.
   - Хүснэгт өөр нэртэй → `js/config.js` доторх `TABLES`-ийн утгыг өөрчилнө.
   - Багана өөр нэртэй → баганыг нэрийг нь өөрчлөх, эсвэл `js/services/` доторх тохирох файлын эхэн дэх `COLUMNS` жагсаалтыг засна.
   - Хүснэгт бүрт `user_id uuid` багана (`auth.uid()` анхдагч утгатай) болон `schema.sql`-ийн төгсгөл дэх RLS policy хэрэгтэй.
   - Санах зүйл: төлөв, ач холбогдлын утгууд (`active`, `todo`, `high` …) өгөгдлийн санд англиар хадгалагдаж, зөвхөн дэлгэц дээр монголоор харагдана.
3. **Нэвтрэлтийн redirect.** *Authentication → URL Configuration* хэсэгт локал/production хаягаа (жишээ нь `http://localhost:5173`) redirect URL болгон нэмнэ. Ингэснээр бүртгэл баталгаажуулах болон имэйл холбоос апп руу буцна.
4. **Дахин ачаалах.** Нэвтрэх дэлгэц гарна (нууц үг, бүртгүүлэх, имэйл холбоос). Нэвтэрсний дараа Тохиргоо → *Өгөгдөл ба холболт* → **Холболт шалгах** нэг бодит хүсэлт илгээж үр дүнг харуулна. Аль нэг хүснэгт ачаалагдахгүй бол мэдэгдэлд хүснэгтийн нэр болон засах аргыг бичнэ.

## 3а. Таны Supabase холболт (бэлэн)

- Төсөл: `cztdncdfhyrctqzpfwob` (ap-southeast-2). `js/config.js`-д Project URL ба **publishable** түлхүүр бичигдсэн — нийтэд ил байж болох түлхүүр; өгөгдлийг RLS хамгаална.
- Таны сан өөрийн бүтэцтэй байсан тул апп-ыг түүнд тааруулсан: `js/services/dbMapping.js` апп-ын талбарыг сангийн багана руу хөрвүүлнэ (жишээ нь `due_date` + `due_time` → `due_at`). `supabase/schema.sql` нь яг энэ бүтцийг тайлбарлана.
- Нэмсэн өөрчлөлтүүд (`supabase/migrations/`): төрсөн өдрийн сануулгын тохиргоо, сургууль (`subjects`, `class_sessions`, `homework`), ажил (`workplaces`, `work_shifts`, `income_entries`, `orders`, `work_contacts`, `work_goals`). Бүгд RLS-тэй.
- Бүх хүснэгтэд RLS асаалттай: хэрэглэгч бүр зөвхөн өөрийн мөрийг харна. Supabase security advisor: асуудалгүй.
- Үлдсэн нэг алхам: Supabase → **Authentication → URL Configuration** дээр сайтын хаягаа (доорх 3б-г үз) *Site URL* болон *Redirect URLs*-д нэмнэ. Үгүй бол бүртгэл баталгаажуулах имэйл буруу хаяг руу буцна.
- Үнэгүй төсөл 7 хоног идэвхгүй байвал түр зогсдог. Тэгвэл Supabase Dashboard → төсөл → **Restore** дарна.
- `preview.html` үргэлж жишээ өгөгдөлтэй session горимд ажиллана — таны сан руу холбогдохгүй.

## 3б. GitHub Pages дээр байршуулах

1. GitHub дээр шинэ repository үүсгэ (жишээ нь `life-os`) ба энэ хавтсын агуулгыг (index.html үндсэн түвшинд байхаар) оруул.
2. Repository → **Settings → Pages → Build and deployment**: Source = *Deploy from a branch*, Branch = `main`, хавтас = `/ (root)` → **Save**.
3. 1–2 минутын дараа сайт `https://<хэрэглэгчийн-нэр>.github.io/life-os/` хаягаар нээгдэнэ.
4. Supabase → **Authentication → URL Configuration**: *Site URL* болон *Redirect URLs*-д дээрх хаягийг яг тэр чигээр нь (төгсгөлийн `/`-тэй) нэм.
5. `js/config.js` доторх `SUPABASE_URL` ба `SUPABASE_ANON_KEY`-г бөглөөд push хий. anon (publishable) түлхүүр нийтэд харагдахаар зохиогдсон бөгөөд өгөгдлийг RLS хамгаална. `service_role` / `sb_secret_` түлхүүрийг хэзээ ч бүү оруул.

`.nojekyll` файл GitHub Pages-д файлуудыг өөрчлөлгүй үйлчлэхийг заана — устгахгүй.

### Утаснаас нэг файлаар байршуулах (хамгийн хялбар)

`node tools/build-preview.mjs --prod` нь бүх апп-ыг Supabase тохиргоотойгоо нэг `dist/index.html` файл болгоно. Тэр ганц файлыг GitHub repo-дoo **Add file → Upload files**-аар хуулж, **Settings → Pages**-д `main` branch-ийг сонгоход хангалттай. Код өөрчлөх бүрт энэ командыг дахин ажиллуулж, шинэ файлыг дахин хуулна.

## 5. AI туслах

**AI загвар холбогдоогүй бөгөөд интерфейс үүнийг нуудаггүй** (чат дотор мэдэгдэл, хариулт бүр дээр “Дүрмийн хариулт · AI загваргүй” шошго). Холбох хүртэл энгийн дүрмүүд таны өгөгдөл дээр тулгуурлан тодорхой командуудыг гүйцэтгэнэ:

| Команд | Жишээ |
|---|---|
| Ажил нэмэх | “Ажил: Баасан гарагт 15 цагт тайлан илгээх чухал #ажил 1 цаг” |
| Үйл явдал нэмэх | “Маргааш 12:30-13:30 Маятай үдийн хоол” |
| Өдрөө төлөвлөх | “Өдрөө төлөвлө”, “Маргаашийг төлөвлө” |
| Долоо хоногоо төлөвлөх | “Долоо хоногоо төлөвлө” |
| Дуусаагүй ажил | “Дуусаагүй ажлууд юу байна?” |
| Статистик | “Статистикаа харуул” |
| Хуваарь асуух | “Маргааш юу байгаа вэ?” |
| Төсөл задлах | “Төслийг задла: Вэбсайт гаргах” — ерөнхий, засварлаж болох жагсаалт өгнө |
| Санамж | “Санаарай: Би өглөө хамгийн сайн төвлөрдөг” |

Задлагч таньдаг үгс: *өнөөдөр, маргааш, нөгөөдөр, ирэх даваа, баасан гарагт, 3 хоногийн дараа, ирэх долоо хоног, 11-р сарын 20-нд*; цаг: *15 цагт, орой 7 цагт, 15:00-д, 14-16 цагт*; хугацаа: *45 мин, 2 цаг, 1 цаг 30 мин, хагас цаг*; ач холбогдол: *чухал, яаралтай, !өндөр, !бага*; ангилал: *#ажил*. Англи хэлбэрүүд (*Friday 3pm !high 45m*) мөн ажиллана.

Өөрчлөлт бүр **санал болгох карт** хэлбэрээр гарч, хэрэглэгч баталгаажуулна (Нэмэх / Засаад нэмэх / Татгалзах). Үр дүн нь мессеж дээр хадгалагдана.

### AI загвар (Claude) — холбогдсон

`supabase/functions/life-os-ai/index.ts` нь Supabase Edge Function хэлбэрээр таны төсөлд байршсан бөгөөд `js/config.js` доторх `AI_ENDPOINT` түүн рүү заасан.

- Нууц түлхүүр: Supabase → **Edge Functions → Secrets** → `ANTHROPIC_API_KEY` (console.anthropic.com-оос авна; хөтөч рүү хэзээ ч гардаггүй).
- Заавал биш: `AI_MODEL` (анхдагч `claude-sonnet-5-5`, хямд нь `claude-haiku-5-5`), `AI_ALLOWED_EMAILS` (зөвхөн эдгээр имэйлтэй хэрэглэгч AI ашиглана).
- AI ажиллахгүй үед (түлхүүргүй, интернэтгүй) Туслах энгийн дүрмүүдээр хариулж, шалтгааныг нь бичнэ.
- AI-ийн санал болгосон ажил, үйл явдал хэрэглэгч «Нэмэх» дарах хүртэл хадгалагдахгүй.

### Өөр AI endpoint холбох



Сервер талын endpoint үүсгэ (жишээ нь LLM-ийг серверийн түлхүүрээр дууддаг Supabase Edge Function) ба `js/config.js` дотор `AI_ENDPOINT`-ийг тохируул. Апп дараахыг илгээнэ:

```http
POST <AI_ENDPOINT>
Authorization: Bearer <хэрэглэгчийн Supabase access token>
apikey: <anon түлхүүр>
Content-Type: application/json

{
  "conversation_id": "uuid",
  "message": "Долоо хоногоо төлөвлө",
  "history":  [{ "role": "user" | "assistant", "content": "…" }],
  "memories": ["Би үдээс өмнө сайн төвлөрдөг"],
  "context":  { "today": "2026-11-01", "timezone": "Asia/Ulaanbaatar", "open_tasks": [...], "events_next_7_days": [...], "active_goals": [...] }
}
```

Хариу нь:

```json
{
  "reply": "Чатад харагдах текст",
  "actions": [
    { "type": "create_task",  "data": { "title": "…", "due_date": "2026-11-06", "due_time": "15:00", "priority": "high", "category": "Ажил", "estimated_minutes": 45 } },
    { "type": "create_event", "data": { "title": "…", "event_date": "…", "start_time": "…", "end_time": "…", "category": "work" } },
    { "type": "breakdown",    "data": { "title": "Төслийн нэр", "project_id": null, "steps": ["…", "…"] } },
    { "type": "create_memory","data": { "content": "…" } }
  ]
}
```

`schedule_day`, `schedule_week`, `review`, `insights`, `link` төрлийн action-ууд мөн зурагдана — яг хэлбэрийг `lib/localAssistant.js`-ээс харна уу. Function дотроо хэрэглэгчийн JWT-г шалгаж, загварын түлхүүрээ хэзээ ч хөтөч рүү бүү гарга.

## 6. Боломжууд

- **Хянах самбар** — нүүрэнд том бичих талбар: өгүүлбэрээ бичихэд огноо, цаг, ач холбогдлыг шууд таньж харуулна, Enter дарахад ажил (цагийн мужтай бол үйл явдал) болж нэмэгдэн самбар тэр даруй шинэчлэгдэнэ; өнөөдрийн ахиц, төлөвлөсөн хугацаа, хугацаа хэтэрсэн ажил, зорилгын ахиц, хурдан нэмэхтэй өнөөдрийн ажлууд, тэргүүлэх ажил, удахгүй болох үйл явдал ба төрсөн өдөр, сэтгэл санааны тэмдэглэл, сүүлийн 7 хоног.
- **Календарь** — сар / долоо хоног / өдөр. Огноо дээр дарахад хуваарь нь гарна, давхар дарвал үйл явдал нэмнэ. Долоо хоног/өдрийн харагдацад хоосон цаг дээр дарж тэр цагт үйл явдал үүсгэнэ, сумтай товчоор өдөр хооронд шилжинэ. Утсан дээр долоо хоног нь жагсаалтаар харагдана.
- **Хийх зүйлс** — монгол/англи өгүүлбэрийг ойлгодог хурдан нэмэх (урьдчилан харах), ач холбогдол, эцсийн хугацаа ба цаг, ангилал, тооцоот хугацаа, төсөл; хайлт, 5 шүүлтүүр, 5 эрэмбэ; Хугацаа хэтэрсэн / Өнөөдөр / Маргааш / Ирэх 7 хоног / Дараа / Огноогүй бүлэг; дуусгах, устгахыг “Буцаах” боломжтой.
- **Зорилго ба төсөл** — зорилго төслүүдийг, төсөл ажлуудыг агуулна; ахиц ажлын гүйцэтгэлээс тооцоологдоно; түр зогсоох, дуусгах, аюулгүй устгах.
- **Сургууль** — гэрийн даалгавар (хичээл, эхлэх/дуусгах өдөр ба цаг, тооцоот хугацаа, төлөв: эхлээгүй/хийж байна/дууссан/илгээсэн, үлдсэн хугацааны тоолуур), хичээлийн хуваарь (гараг, цаг, анги, лекц/семинар, багш), хичээлүүд (өнгө, багш); нүүр хуудсанд дараагийн хичээл ба ойрын даалгавар, мэдэгдэлд 2 хоногийн дотор дуусах даалгавар.
- **Ажил** — 5 хэсэг:
  - *Ээлж, цаг* — ажлын газар бүрийн өнгө, цагийн хөлс эсвэл сарын цалин, цалин/урьдчилгааны өдөр; долоо хоногийн ээлжийн хуваарь (шөнийн ээлж, завсарлага, нэмэгдэл, долоо хоног бүр давтах), ажилласан ба төлөвлөсөн цаг, дараагийн ээлжийн карт.
  - *Цалин, орлого* — сараар: олсон орлого, ажилласан цаг, хүлээн авсан мөнгө, хүлээгдэж буй цалин; ажлын газраар задаргаа, цалингийн өдрийн тоолуур, орлогын бүртгэл. Цагийн хөлстэй ажлын цалинг ээлжээс тооцдог тул давхар тоологдохгүй.
  - *Захиалга* — Шинэ → Бэлтгэж байна → Бэлэн → Хүргэсэн самбар, нэг товчоор дараагийн шат, үнэ ба үлдэгдэл төлбөр, хүргэх өдөр/цаг, хаяг; хоцорсон захиалга raspberry өнгөөр.
  - *Төсөл, уулзалт* — «Ажил» ангилалтай хийх зүйлс, ажлын уулзалтууд (календарийн «Ажил» үйл явдал), хамт ажиллагсдын холбоо барих мэдээлэл, тэмдэглэл.
  - *Ойрын зорилго* — 7 хоног/сарын хэмжигдэхүйц зорилго: цаг, орлого, хүргэсэн захиалгыг автоматаар тоолно, бусдыг −/+ товчоор; хугацааны хэмнэл (түрүүлж/хоцорч байна).
  - Ээлж ба захиалга календарьт харагдаж, өдрийн төлөвлөгч ээлжийн цаг дээр юм тавихгүй; нүүр хуудсанд «Ажил» карт, мэдэгдэлд ойрын ээлж, хүргэх захиалга, цалингийн өдөр, дуусах гэж буй зорилго.
- **Тэмдэглэл** — сэтгэл санаа (1–5), эргэцүүлэл, талархал; сарын сэтгэл санааны зураг, дараалал, хайлт, шүүлтүүр.
- **Төрсөн өдөр** — тоолуур, нас, хамаарлаар шүүх, эрэмбэлэх, хүн бүрийн сануулга (тухайн өдөр … 2 долоо хоногийн өмнө), календарь болон мэдэгдэлд харагдана.
- **Мэдэгдэл** — хугацаа хэтэрсэн, өнөөдөр дуусах, ойрын үйл явдал, төрсөн өдрийн сануулга, зорилго/төслийн хугацаа; уншсан/уншаагүй, хаах, шууд дуусгах; үйл явдлаас 10 минутын өмнө хөтчийн сануулга (заавал биш).
- **Шинжилгээ** — 7/30/90 хоног: дууссан ажил, гүйцэтгэл ба хугацаандаа дуусгалт, ажилласан хугацаа, өдрийн график, сэтгэл санааны хандлага, гарагийн хэмнэл, ангиллаар хугацаа, ач холбогдол, зорилгын ахиц, бичвэр тайлан, хүснэгт, CSV, хэвлэх.
- **Тохиргоо** — өнгөний горим, долоо хоногийн эхлэл, 12/24 цаг, ажлын цаг, ажлын анхдагч утга, хөтчийн сануулга, холболтын төлөв ба шалгалт, JSON экспорт, жишээ өгөгдөл / цэвэрлэх (session горим), товчлол.
- **Хаа сайгүй** — нийтийн хайлт (`/`), шинэ ажил (`n`), “Шинэ” цэс, гэгээлэг/харанхуй горим, гарнаас удирдах боломжтой цонхнууд, компьютер → таблетын дүрс цэс → утасны доод цэс.

## 7. Дараагийн алхмууд (заавал биш)

- **Мэдэгдлийн уншсан төлөвийг синк хийх**: `notification_states (user_id, notification_id, read_at, dismissed_at)` хүснэгт нэмж `notificationsService.js`-ээс дуудна.
- **Realtime**: service дотор `supabase.channel(...).on('postgres_changes', …)` гэж бүртгүүлээд өөрчлөлт ирэхэд `store.replace()` дуудна.
- **Bundler**: Vite руу шилжвэл `lib/supabaseClient.js` доторх CDN import-ийг `import { createClient } from '@supabase/supabase-js'`-ээр солино.

## 8. Гараар шалгах жагсаалт

- Хажуугийн цэс (компьютер), дүрс цэс (таблет), доод цэс + “Бусад” (утас)-аар бүх хуудсаар орох.
- Ажлууд: `Баасан гарагт 15 цагт тайлан илгээх чухал #ажил 45 мин` гэж хурдан нэмэх, засах, дуусгах → Буцаах, устгах → Буцаах, шүүлтүүр ба эрэмбэ.
- Календарь: сарын харагдацад огноо дарах, сумтай товч, долоо хоногт хоосон цаг дарах, өдрийн харагдац, үйл явдал нэмэх/засах (дуусах цаг эхлэхээс өмнө бол алдаа заана).
- Зорилго: зорилго → төсөл → ажил шууд нэмэх; ахиц шинэчлэгдэнэ.
- Туслах: “Ажил: …”, “Өдрөө төлөвлө” → блок нэмэх, “Төслийг задла: …” → ажил үүсгэх.
- Тэмдэглэл, Төрсөн өдөр (2-р сарын 30 татгалзана), Мэдэгдэл (бүгдийг уншсан болгох), Шинжилгээ (хугацаа солих, CSV), Тохиргоо (өнгө, 12 цагийн формат).
